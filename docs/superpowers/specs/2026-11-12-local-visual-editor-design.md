# 本地作品集可视化编辑器设计

## 意图

把当前管理页从“中间表单 + 右侧实时预览”改成单画布的直接编辑器。用户看到接近公开页面的内容，点击文字即可编辑，点击图片即可替换或调整；通过工具栏添加内容组件，并拖拽组件改变顺序。

## 当前实现

管理页由 `scripts/local-admin/app.js` 按当前表单动态生成编辑项；`scripts/local-admin/preview.js` 将草稿另行渲染到右侧预览。内容数据已按页面及作品拆分为 JSON，本地 API 负责校验、读写和上传图片。用户希望消除表单与预览的并排感，改成类似 Word 的“所见即所得”编辑体验。

## 目标

- 全站主要可编辑内容使用中央画布：首页、About、Contact、作品分类/列表、作品详情。
- 在画布上直接编辑标题、段落、分类名、作品文字及联系信息；编辑后立即更新画布。
- 用工具栏添加正文、图片、图文组合、图片组、引用、链接等已有内容组件。
- 组件通过拖拽手柄在页面结构内排序，并可删除；作品列表和分类列表也可排序。
- 图片在画布中点击后可选已有图片或上传替换；添加图片组件可在当前位置加入。
- 提供按页面上下文显示的轻量属性面板/弹层，用于图片焦点、轮播时间、模板、替代文字、链接、日期、SEO 等不适合直接内联的设置；不再显示一块独立预览区。
- 保持现有 JSON 内容格式、本地写入 API、图片目录、保存按钮和安全边界兼容。
- 保持公开页面现有模板、极简视觉及响应式布局；编辑器不创建任意像素定位，避免破坏发布后的版式。

## 非目标

- 不把网站改成任意画布尺寸/自由摆放的通用网页构建器。
- 不修改访客端作品集设计、数据模型或静态发布流程。
- 不移除本地 API 校验，不自动上传或发布网站。

## 方案比较

1. **结构化可视画布（选定）**：中央画布用公开页对应的页面结构呈现内容，文字可直接编辑，组件可添加、替换和拖拽排序；左侧仅负责选择首页/About/Contact/分类/作品。非正文设置用轻量属性面板。用户选择将全站内容纳入中央画布。该方案同时满足视觉化操作与现有固定模板、响应式结构。
2. **先仅改作品详情**：只把作品详情编辑改成画布，其他页面沿用表单。实现范围更小，但编辑方式会在一个后台内割裂；用户已选择全站画布，因此不采用。
3. **自由摆放式页面构建器**：允许元素任意拖放到坐标并调整大小。它会创建新布局模型、增加移动端适配负担，也容易改坏既有网站风格；本次不采用。

## 交互与界面

- 顶栏：当前页面名、撤销/重做（若可在本地草稿状态安全实现）、保存状态、保存按钮、预览作品集。
- 左侧导航：网站设置、Home、About、Contact、分类及所选分类下的作品。此区域只用于切换编辑对象，不放字段表单。
- 中央画布：展示所选页面内容。文字区域聚焦后直接输入；选中区块时显示边框、拖拽柄和上下文操作按钮。
- 插入工具栏：文本、图片、图文、图片组、引用、链接。工具添加结构化组件，不改变公开模板布局。
- 属性面板：只在选中需要属性的元素或页面设置时显示为窄侧栏/弹层；没有选中对象时不占用画布宽度。
- 操作流程：选择页面 → 点击文字直接编辑或选中图片/组件 → 插入/替换/排序 → 检查同一画布效果 → 保存到本机。

## 页面映射

- **Home**：整页背景图预览和轮播列表；拖动背景排序，点图替换/上传；选中背景后在属性面板调整缩放、位置和替代文字，另可设置轮播时间。网站标题/简介通过选中网站设置入口编辑。
- **About**：姓名、经历、日中段落、照片均在页面对应位置编辑；可增加/删除经历与段落并排序。
- **Contact**：Instagram、Email、WeChat 在页面位置直接编辑。
- **分类/作品列表**：分类名称和作品缩略图标题文字直接编辑；分类顺序、作品顺序通过拖拽调整；选中作品进入其详情画布。
- **作品详情**：标题、类型、日期和简介可内联编辑；现有首图和图库保持在标题后的固定图片区；正文中的图片区、正文、图文、引用、链接等 `ContentBlock` 可从工具栏添加并在正文区域内拖拽排序。此边界沿用当前 JSON 的 `image` / `gallery` / `sections` 字段，不跨字段重排。
- **特殊字段**：模板选择、SEO 字段和内部 URL slug 放入属性面板；不允许在画布直接改 URL slug。

## 数据、保存与校验

- 中央画布与属性面板都读写同一份本地 draft；不再维护一份独立的 preview 数据副本。
- 所有直接编辑立即更新 draft，画布同步显示；保存时复用现有 API 和结构化 JSON。
- 仍由服务器校验内部链接、本地图片路径、必要字段、缩放值和内容区块类型；失败时保留草稿并显示错误。
- 拖拽排序只改变数组顺序及作品/分类 order，不引入自由定位字段。
- 上传图片仍进入 `public/images/home/`、`about/` 或 `works/<category>/`；删除仍遵循“未被引用才可删除”。

## 验收标准

- 管理页不再出现左/中表单与右侧预览并排布局；所选页面在中央画布内直接编辑。
- 文字输入后画布显示新内容，无需切到另一块预览区域。
- 用户可添加、删除和拖动已有类型组件；重新打开后台后，保存内容仍存在并可构建。
- 首页背景、分类、About、Contact、作品列表与作品详情均可在画布中编辑其主要内容。
- 属性面板只服务于页面/图片/模板等上下文设置，不成为第二套预览。
- 拖拽结果仍符合公开页面响应式模板；不出现任意坐标布局。
- 本地入口、API 安全边界和静态构建排除后台的行为保持不变。

## 实现选择

- 尽可能重用现有公开页面 class 与模板，画布增加可访问的编辑边框、拖拽手柄和插入按钮。
- 用浏览器原生 drag/drop 实现结构化排序，不新增第三方编辑器依赖。
- 作品详情是现有 `ContentBlock` 最丰富的区域；先以它建立可复用的编辑组件映射，再应用到 About、Contact、Home 和列表页。
- 详情首图/图库固定在标题之后；仅正文 `sections` 组件互相排序，以保留当前数据结构和公开模板。
- 现有编辑 API 与 JSON schema 可复用，主要变更集中在 `scripts/local-admin/index.html`、`app.js`、`preview.js`、`styles.css`；必要时添加清晰分工的编辑器模块。
