# 本地作品集管理界面设计

## 目的

作品集内容由项目所有者在本机维护。管理界面是一个单独页面 `/admin/`，从本地预览网站的“管理”入口在新标签页打开。访客版不显示此入口。管理操作直接保存到项目内容文件与 `public/images/`，不依赖 Sanity 或其他托管 CMS。

## 目标

- 在一个本地管理页面内维护网站标题与文案、首页背景图片轮换及图片缩放/位置、About、Contact、分类和作品资料。
- 为每件作品选择预设详情模板，编辑文字/图片区块并调整顺序；发布前能在作品集样式中预览。
- 能新增、替换、移除作品图片，并使用按用途与作品分类的现有图片目录。
- 把本地内容文件作为唯一可编辑来源；公开网站仍由 Astro 静态构建并按现有 GitHub Pages 流程发布。
- 管理界面与写入接口只在 Astro 开发服务器中提供；构建后的公开网站不包含可用的文件写入能力。

## 不在本次范围

- 不创建或部署远程管理网站，不添加账号系统、外部 API 密钥或付费服务。
- 不推送 GitHub、不部署网站、不删除已创建的 Sanity 云项目或其数据；Sanity 项目保持闲置，直到用户另行决定。
- 不改变已确认的极简视觉与响应式公开页面设计。

## 已评估的做法

1. **同一个 Astro 开发服务上的 `/admin/` 独立页面（选定）**：本地入口新标签打开管理页面，内容预览在管理页面里显示。仅需启动现有本地预览服务，入口和写入 API 均由开发模式控制。逻辑界面分开，但地址和服务进程相同。
2. **独立本地管理服务**：管理页在另一个端口运行，目录和服务与作品集完全分开。职责隔离更明确，但启动、关闭和排查都要维护第二个服务，与当前“尽量省事”的本地工作方式不符。
3. **托管 CMS**：适合跨设备登录编辑，但需要账户、在线内容源及访问配置；用户已表达希望本机管理，因此不采用。

## 内容与文件结构

- 将当前 `src/data/portfolio.ts` 中的可编辑资料迁入可由本地 API 安全写回的结构化 JSON 内容文件；迁移后这些 JSON 是唯一源数据，Astro 页面从这些文件读取。
- 网站全局设置、分类、作品、About、Contact 分开管理。每件作品的详情资料保存在按分类与 slug 组织的文件中；模板标识、排序后的区块、图片路径与图片呈现设置都是作品记录的一部分。
- 图片继续放在 `public/images/home/`、`public/images/about/` 和 `public/images/works/<category>/`；上传文件只能保存到允许的媒体目录，避免表单字段构造任意文件路径。
- 已有公开页面数据不丢失。引入 JSON 时以 `portfolio.ts` 的现存内容生成初始文件，并在切换构建读取来源后再移除旧数据副本，防止出现两套手动维护的来源。

## 管理界面与预览行为

- 开发模式时，公开页面显示一个仅本机可见的管理入口；点击后在新标签打开 `/admin/`。
- 管理页面按网站设置、首页、About、Contact、分类、作品进行导航。支持新增、编辑、调整排序和保存。
- 首页背景支持多图轮换、替换、缩放和位置调整，并在保存前预览效果。
- 作品编辑表单支持选择预设详情模板、编辑字段、添加/删除/排序文字与图片区块；可切换到详情页预览。
- 修改在保存前属于表单草稿；保存后直接更新本地文件。保存后的公开站点预览由本地 Astro 页面反映。正式上线仍需用户审阅并按既有流程发布。

## 安全与运行约束

- `/admin/` 和写入接口必须在构建后禁用；通过环境编译/服务端检查双重确认，不仅依赖隐藏按钮。
- 本地写接口只绑定回环地址（`127.0.0.1`），并检查 Host / Origin；不允许局域网其他设备连入，也不要求开放给手机编辑。严格限制可写目录、文件名、字段和上传格式。删除媒体前确认文件确实位于允许目录且未被其他内容引用。
- 不记录或暴露机器绝对路径、令牌或任意文件内容；Sanity 凭据不参与新流程。
- Astro 公开页面仍输出静态 HTML；`npm run build` 需验证不会因本地文件写入 API 改为依赖生产 Worker。

## 验收标准

- `npm run dev` 后可从公开页新标签打开独立管理页面，生产构建不显示本地管理入口。
- 可编辑并保存全局文字、About/Contact、首页图像列表与焦点设置、分类/作品字段、预设模板和详情区块顺序。
- 图片上传与替换后仍位于预期分类媒体目录，页面路径可用。
- 未保存的表单更改可在管理页面预览；保存后刷新仍保留，重新构建后静态页显示相同内容。
- `/admin/` 写入接口在生产构建中不可操作；现有公开页面与移动布局保持正常。

## 留给实现的选择

- 可维护性和可理解性优先选择数据文件布局、表单组件与本地 API 实现；依赖应尽量沿用 Astro 现有依赖。
- 如果现有详情数据或图片引用无法无损迁移，先停止移除旧源数据并记录阻塞点，不得静默丢字段或删除图片。
