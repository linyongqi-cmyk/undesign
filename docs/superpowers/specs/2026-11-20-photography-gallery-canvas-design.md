# 摄影图集上下两区与画布图库交互设计

## 目标

摄影图集作品详情页在标题下拆成上部内容区和下部图库区。管理画布与前台共享相同的内容顺序、上部宽度、图片顺序、图片比例和说明布局；画布专用控件不占用作品内容空间。

## 页面结构

- 作品标题保持固定并显示在最上方。
- 上部内容区默认宽度为 `45vw`，通过摄影画布的“上部宽度”控件调整并保存。区内使用现有 Puck `content` 组件和拖放排序逻辑，允许添加当前所有文字、媒体及其他可用组件。
- 下部为独立双列瀑布图库，默认占满作品详情可用宽度，与上部保持现有图库区的垂直分隔。每项只显示图片及其既有说明/链接文字；桌面端两列，小屏单列并保持原顺序。
- 摄影模板不显示“选择文字组件”群组创建工具。图片区仍保存为专用 `gallery` 数组，不作为 Puck 组件，也不开放群组创建。

## 画布图库操作

- 摄影画布始终显示图库区域，包括图库为空时；编辑辅助的“添加图片”按钮放在图库区域顶部并以覆盖/工具样式呈现，不改变前台内容流或图片尺寸。
- 点击按钮打开现有图片选择/上传流程；成功选图后按当前顺序追加到 `root.props.gallery`。取消选择不新增空项。已有右侧图库数组编辑入口在摄影模板中隐藏，避免维护两套入口。
- 每张图库图片可直接拖动到另一张之前或之后；落点更新 `root.props.gallery` 顺序并纳入现有草稿、撤回、保存机制。没有图片时仍可从添加按钮开始。
- 图库项复用普通图片组件的画布图像编辑、替换、裁切、说明和图片链接设置；不显示整体缩进、显示模式/宽度和悬停放大操作。图库渲染忽略旧数据中这些展示字段，但不清除，避免无关数据丢失。

## 数据与兼容性

- 新增根属性 `photographyIntroWidth`（单位 vw，默认 45）；在 `workToPuckDocument` / `puckDocumentToWork` 间往返并写入摄影作品 JSON。
- 继续使用现有 `gallery` 数据；已有图库图片顺序、图片说明、裁切和链接文字保持不变。正文中已有普通图片不会自动迁入图库。
- 前台与 Puck 预览读取相同的宽度属性和 `gallery` 数组；使用同一图库平衡函数，保持列分配顺序一致。
- 仅对 `photographyGallery` 模板启用以上行为，其他模板的根图库字段、群组工具、拖拽和布局不变。

## 检查

- 管理画布核对已有摄影作品和空图库作品：标题固定、上部默认 45vw、组件拖拽排序、宽度修改、图库新增及图片内拖排序、图片替换/裁切/说明/链接操作，且三项禁用设置不出现，草稿保存/重载一致。
- 对照同一份保存内容检查前台和画布的上部宽度、内容顺序/间距、双列图库顺序及每项图片/说明；检查小屏单列和空图库添加入口不出现在前台。
- 运行 `npm run build`；按项目流程核对本地前台和管理页。不运行额外测试，除非实现过程中发现必须的回归检查。

## 影响范围

前台详情模板与样式、Puck 管理画布及摄影作品数据映射。属于新增布局和编辑能力，预计前端与管理端各递增 MINOR；最终版本以实施时项目版本为准。只做本地修改，不发布或推送。
