## 第一批　保护素材和站内链接

### 1. 上传完成后立即保护草稿素材（P1）

**定位**　`scripts/local-admin/storage.mjs` 的 `saveImage`、`saveVideo`、`retainHistoryMedia`、清理和显式删除函数。对应上传路由在 `scripts/local-admin-integration.mjs`，客户端入口在 `scripts/local-admin/api.js`。

- [ ] 在副本的 A 上传 GIF 和 MP4，保持草稿未保存。B 修改另一作品并保存。记录上传路径、文件是否还在、A 的图片和视频能否继续显示。
- [ ] 在服务端上传成功返回前登记待使用素材。登记须覆盖图片两种上传方式及视频。清理时统一检查已保存内容、回收站、撤回历史和待使用素材。保护应跨开发服务重启恢复。可用项目本机的待上传清单，且让文件与登记失败时的处理一致。
- [ ] 素材只有在已保存引用能接续保护，或已确认无任何草稿、历史与回收站引用时，才退出待上传保护。标签页关闭、服务重启或登记状态未知时保守留存。核对显式删除也会尊重保护。
- [ ] 重跑 A/B 场景，再用 A 保存并刷新，确认媒体路径仍有效、GIF 保留动画、视频能读取。加查 A 保存后撤回、B 再保存、服务重启和手动清理。验证一个确实无引用、无保护的临时素材仍能按原流程清理。

### 2. 移动作品同步更新站内链接，回收前检查引用（P1）

**定位**　`scripts/local-admin/storage.mjs` 的 `moveWorkRecord`、`removeWork`、`renameWorkRecord`，`src/lib/content/rewrite-work-links.js`，以及 `scripts/local-admin/app.js` 的草稿、Puck 文档与历史同步。

- [ ] 在副本创建作品 A 和引用 A 的作品 B。准备普通站内链接、Research Log 锚点、一个群组内链接和带查询或片段的旧路径链接。移动前记录各入口指向的位置。
- [ ] 复用已有改名时的引用遍历，支持从旧分类及 slug 映射到新分类及 slug，保留查询和与原路由无关的片段。Research Log 的作品链接使用分类页锚点，按目标分类生成地址。移动前准备并校验最终内容视图，检查自引用、嵌套区块、同时移动和改名。
- [ ] 把作品路径、引用改写及媒体复制作为一次关联操作处理，失败时恢复本次变动。成功后把相同映射同步到已保存基线、草稿、Puck 文档和撤回历史，避免后续保存重新带回旧路径。
- [ ] 移入回收站前查找仍在线的其他作品对目标的引用。发现引用时，阻止提交并列出相关作品，供编辑者先调整。回收站恢复沿用冲突校验。
- [ ] 移动后刷新前台并点击 B 的链接，确认能到新地址。复验跨普通分类和 Research Log、移动后改名、撤回再保存、被引用时回收被阻止，以及解除引用后回收恢复。运行 `npm run build`，站内引用校验须通过。

- [ ] A/B 打开同一作品。A 改标题并保存，B 用旧版本改类型并保存，记录标题变化和界面反馈。

- [ ] 冲突时返回可识别的冲突状态和记录标识，提示哪个内容已被其他标签页更新，保留 B 的草稿和撤回历史。重新读取、比较改动、再提交由用户控制。成功后刷新本次写入记录的版本。

### 4. 顶栏保存先校验整批，再提交（P2）

**定位**　`scripts/local-admin/app.js` 的 `saveAllDirty`，本机管理路由、`storage.mjs` 和现有只读校验 `validateWorkContent`。

- [ ] 用两个待保存作品复现。第一个标题合法，第二个设为指向不存在作品的链接。点击保存后比对两个文件，记录错误提示和已经落盘的内容。
- [ ] 将顶栏提交整理为一份变更清单，由服务端按预期最终的分类、作品、媒体和链接视图验证整批；复用第 3 项的版本检查。验证前保留现有 slug 格式、重复目标、媒体存在和旧格式兼容规则。任何记录校验失败时返回记录及字段位置，全部草稿保留。
- [ ] 校验通过后，在同一保存流程内集中写入。暂存本批文件和原状态，以便普通写入失败时恢复。把清理放到提交成功之后。若恢复中也出错，明确报告已写、已恢复及待人工核对的文件，避免用同一条保存提示掩盖结果。
- [ ] 复测合法记录在另一记录校验失败时完全不变。再模拟写入中断、修正后重试、同批新建目标与引用、移动与改名，以及提交成功但清理失败。校对磁盘、管理页、保存提示和重载结果。
