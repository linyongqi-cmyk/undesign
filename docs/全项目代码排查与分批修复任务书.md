# Astro 作品集全项目代码排查与分批修复任务书

## 目标与范围

覆盖前台、管理端、共享渲染、内容与媒体存储，以及静态构建和部署配置。先建立基线并登记问题，再按影响分批修复。保留现有极简视觉、响应式布局和作品内容。架构调整、内容迁移及大范围重构列入待讨论事项。

当前实际内容源为 `src/data/content/` 下的 JSON，由 `src/lib/content/index.ts` 读取。项目规则中提到的旧路径 `src/data/portfolio.ts` 已不存在。图片以 `public/images/` 中的文件为准。

## 执行任务

| 顺序 | 排查任务 | 验收标准 |
|---|---|---|
| 1 | **建立基线**。记录本地 Node 版本、构建结果和生成页面数。检查根路径和 GitHub Pages 子路径两种构建，记录已有控制台错误、失败请求和缺失资源。涉及保存、删除和回收的操作在独立临时副本进行。 | 每条基线包含命令或页面、实际结果和环境限制，后续能用相同条件复查。当前工作目录缺少 Git 元数据，使用副本保留修改前基线。 |
| 2 | **检查管理端与数据保存**。复核 GIF 选择、上传、加入群组和保存重载。检查媒体拖入、混排模板切换、作品移动、摄影说明、撤回重做、保存失败后重试，以及两个标签页对素材引用的保护。追踪校验、持久化和清理顺序。 | 保存后重载保留内容、顺序和引用。失败能够重试，已有数据仍可读取，草稿、历史或回收站仍引用的媒体得到保留。 |
| 3 | **检查前台和画布一致性**。覆盖首页、About、Contact、五个分类及全部生成的详情路由。按网格、瀑布流、研究日志、摄影图集和复杂混排选择代表作品，同作品比对桌面、平板和手机视口。 | 核对文本、媒体顺序、裁切、说明位置和布局。独立详情组件间距为 12px，内容群组内部为 0，媒体说明沿用自身设置。编辑辅助控件不挤占作品内容。 |
| 4 | **检查交互、资源和代码质量**。检查导航、键盘焦点、灯箱、轮播、悬停放大、链接、favicon 和字体请求。检查重复渲染逻辑、频繁监听器、首屏媒体传输及前台是否打包管理端代码。检查 sitemap、子路径资源引用及静态产物中的管理端隔离。 | 每项缺陷都有复现条件和代码定位。性能改动提供同条件的前后指标，例如首屏传输量、请求数或脚本体积。涉及旧数据的优化验证兼容性。 |
| 5 | **按优先级修复并回归**。P0 为构建失败、数据丢失或误删，P1 为主要功能失败或明显显示偏差，P2 为局部缺陷及有证据的性能、维护性问题。每批只处理同一成因或同一模块，按 P0 → P1 → P2 推进。 | 每批保留修复前后的结果，运行 `npm run build` 并复查受影响页面。改动本地管理服务后重启 Astro，核对运行中的 API、保存和重载。改动共享渲染后复查同作品双端。 |

## 问题清单与交付

- 每条问题记录优先级、影响范围、文件或页面、复现步骤、预期与实际结果、修复方案和验证证据。浏览器或素材不可用时，标记「未验证」并写明卡点。
- 沿用现有构建和本地页面检查流程。需要额外自动化测试时按项目流程确认，优先复用已有存储、编辑器和灯箱测试。
- 交付时列出已修复、待讨论和未验证事项，更新根目录的 `交接.md` 与 `修改记录.md`。按实际变更分别更新前端和管理端版本，并记录两个版本及发布状态。GitHub 推送和上线须经用户明确要求。

本次交付为任务书，已核对项目结构、工作流程和部署配置。构建、浏览器检查和缺陷复现将在任务书执行阶段进行。
