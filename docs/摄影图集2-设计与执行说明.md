# 摄影图集2：设计与执行说明

日期：2026-11-21。用途：交给后续 AI 在当前 Astro 项目中实施。本文件最初为设计和执行交接，模板随后已按说明实现。后续用户明确右侧图片栏宽度以视口右侧 2vw 留白边缘为锚点，向左占 53vw；左侧文字栏起点不动并扩展填满剩余空间，列间距为 48px；以下尺寸描述均以此最新要求为准。

## 1. 任务目标与边界

用户明确要求：

- 新增独立模板「摄影图集2」，保留现有「摄影图集」和「图文分栏」。
- 整体类似图文分栏，但交换左右位置：左侧文字，右侧为可自由编排的内容区（以图片为主，也可放文字、备注、链接或媒体组件）。
- 文字栏比现有图文分栏更窄；右侧图片栏宽度为 **53vw**，右边缘对齐屏幕右侧 2vw 留白边界。
- 每张图片的可见展示高度不得超过 **90vh**。
- 保留现有极简视觉、响应式布局，以及管理画布与前台的所见即所得。

建议默认值（是本文件的设计建议，不是用户已确认的细节）：

- 右栏按 `photographyGallery2Sections` 的有序组件列表单列排列；图片只是其中一种组件，可与文字、备注、链接等自由混排并拖动排序。右上“添加图片”按选择顺序追加图片组件。旧数据没有 sections 时回退到 gallery 图片。
- 左文右图顶部对齐，文字正常随页面滚动，不新增 sticky、独立滚动或固定定位。
- 图片在栏内靠左对齐；受高度限制时允许图片比栏窄，完整保留现有裁切视口，不拉伸、不新增裁切。
- 新模板复用现有摄影点击放大开关及摄影说明；旧作品缺省关闭。普通图文分栏、文章模板不因此获得摄影点击放大。
- 手机单列时先标题与正文，再图片；优先沿用现有 720px 断点，但空间预算不足时应更早折行。
- 不新增图片宽度设置面板，53vw 是模板布局规则；旧模板的 UP/vw 字段仍只控制原模板上部介绍宽度。

如用户对上述建议提出不同意见，先修订本文件再实施相关部分。不要将建议写成已经获得用户确认的要求。

不在范围内：重做整个管理端、改变旧模板的宽高、替换素材、自动迁移所有摄影作品、扩大放大入口到所有图片组件、修改现有放大层的尺寸算法或说明样式、发布网站。

## 4. 方案与数据设计

推荐新增模板标识 `photographyGallery2`，中文标签「摄影图集2」。继续使用现有摄影作品数据结构：左文读取 workBodySections(work)，右图读取 gallery；不新增第二套图片数组，不保存派生列数据。

推荐复用旧摄影图库的编辑能力，增加明确的布局变体（如 singleColumn），由外层新模板布局放置文字与图库。旧变体默认仍为原双列，不改变原有调用结果。必要时抽取小型共享布局规则，避免借本次任务重构整个编辑器。

不推荐直接把 splitDetail 完整复制为新模板：其图片可能在 root:left、leftSections 或带 __galleryImage 的 ImageBlock 中，既有摄影说明和图库预览则围绕 gallery 工作；这样会扩大说明丢失、重复图片、切换失败的范围。不推荐只给旧摄影模板加一个全局 CSS 类而不保留独立模板值，因为用户要求可选择的第二模板。

建议保存的数据示意（不是要求添加示例作品）：

```json
{
  "template": "photographyGallery2",
  "photographyLightboxEnabled": false,
  "gallery": [
    { "src": "images/works/photography/example.webp", "alt": "", "photographyDescription": "" }
  ],
  "sections": []
}
```

保留现有 captionSettings、linkLabel、cropAspect、cropScale、cropPosition、hoverZoom 等合法字段。字符串形式的旧图库条目仍应兼容。摄影说明不能被普通 imageData 转换或字符串简写过程吞掉；尤其核对 puckDocumentToWork 中按字段判断是否简化为字符串的逻辑。

### 模板切换契约

- 摄影图集 ↔ 摄影图集2：只改变模板与布局；gallery 顺序、裁切、说明、链接、开关和正文保持，UP/vw 的旧值保留但不在新模板起作用。
- 图文分栏 ↔ 摄影图集2：不能用 DOM 左右位置决定数据字段。当前 splitDetail 的 root:left 是媒体区域，root:right 是正文区域，必须先按原契约导出，再导入目标结构。
- splitDetail 媒体区除图库图片外可能有视频、轮播、群组、免责声明；不能在切换中静默丢弃。建议将无法表示为 gallery 的区块保留到 sections，按稳定顺序呈现；这是安全保留内容的默认方案，切回不保证自动还原原来的列归属。若执行时无法可靠保留，应阻止该次切换并说明具体不支持的内容，而不是保存残缺作品。
- 旧 leftSections 在新模板中的处理必须同时覆盖读取、前台和保存。建议按现有非分栏转换方式合入正文区，并避免与 workBodySections 重复；不能出现画布有内容、前台漏内容。
- 模板切换应作为一次既有历史操作，可撤回、重做；不直接调用保存接口绕过草稿。
- 连续切换、未保存切换再撤回、保存后重载均需验收；不得继续让仅针对 splitDetail 的迁移代码错误重复搬运图库。

## 5. 设计步骤：尺寸与响应式

### 5.1 先计算内容宽度预算

vw 是浏览器视口宽度的百分比，不是右栏或管理画布宽度百分比。当前 CSS 中 --sidebar 为 20vw，splitDetail 原图片列为 45vw、列间距为 48px；主内容还有边距。必须读取实际 SiteLayout 和计算样式后定参数。

右图栏宽度 I=53vw，并贴齐页面内容区右边缘（屏幕右侧留白 2vw）；文字栏左边缘保持现状，以 flex 填满两列之间的剩余空间，列距 G=48px。可用内容宽度不足时图片栏按现有规则收缩或切为单列，不允许挤入导航或出现横向滚动。不把 53vw 改写成 55% 后声称符合需求。

布局参数：右侧图片栏 53vw 且右缘贴齐 2vw 页面留白边缘、列间距 48px；文字栏从当前左缘起弹性扩展，160px 为可读下限。若当前主内容边距导致常用桌面尺寸始终无法接近 53vw，应展示实测宽度并说明取舍，局部调整本模板空间或与用户讨论，不能悄悄全局缩小侧栏。

建议通过模板私有变量集中表达尺寸：--photo2-media-target、--photo2-text-width、--photo2-column-gap。媒体列采用可收缩轨道，所有子项 min-width:0；长链接、日文与中文连续文字应可换行。避免同时写两个硬 vw 再叠加 gap。

### 5.2 图片视口与高度约束

90vh 约束正文中每张图片的最终可见视口（裁切框），不表示整组图库高度，也不要求缩小现有全屏放大层。媒体说明在图片外正常排版，不计入图片高度，不裁掉文字。

不能只写 img {width:100%;max-height:90vh}：同时固定宽高可能改变比例，裁切图的内联 height:100% / max-height:none 也会覆盖。应限制实际外框，并让图片按原图比例或用户 cropAspect 等比缩放。

可统一计算最终框宽 W=min(右栏可用宽度, Hmax×r)，高 H=W/r；r 为 cropAspect（有效时）或原图宽高比，Hmax=90vh。该表达为算法约束，执行者选择 CSS aspect-ratio / min() 或共享尺寸辅助实现，不必为此新增一套浏览器专用计算器。比例缺失时提供安全占位与加载后更新，避免 Infinity、NaN 和跳动。

裁切后的框完整保留；cropScale / cropPosition 仍作用于框内图片，overflow:hidden 只用于裁切框，不能裁掉外部 caption 或工具栏。图片标签链接锚定最终可见框的右下角，不锚定占满 53vw 的空白栏。

手机先用 90vh 回退，可叠加不超过 90vh 的 90svh 作为稳定限制，避免地址栏伸缩导致布局跳动。若用 dvh，应实测并说明动态变化。所有模式仍需实测可见框高度 ≤ 0.9×视口高度。

### 5.3 手机与管理画布

窄屏单列宽度为可用容器宽度，不坚持 53vw；保留上下顺序、图片比例和 90vh 上限。横屏手机、低高度笔记本同样检查高度。

前台与画布使用相同布局规则和断点语义。在相同内容展示宽度与有效视口下比较；管理侧栏不能让 vw 意外按外层编辑器窗口计算。先确认现有画布是否有 iframe / transform / 缩放，不能简单给管理端单独写一个近似 65% 的布局。编辑器窄容器需要同一套可用宽度收缩规则；工具按钮和拖放占位不能改变作品内容尺寸。

## 6. 点击放大与旧交互兼容

建议仅两种摄影模板共享摄影能力判断，布局仍区分各模板；普通图文分栏和文章维持原行为。不要把分类 photography 等同于模板能力，也不要因模板切换自动开启开关。

前台需同时满足支持摄影能力的模板与 photographyLightboxEnabled===true 才生成入口。当前事件绑定只查询旧模板；新模板必须有对应 gallery 容器、图片 ID、数据属性与 frameSelector，使用幂等绑定防止 astro:page-load 后重复打开。

复用 openPhotographyLightbox，按实际可见图片排列传入 items；单列就是从上到下。键盘左右循环、点击切图、Esc、背景关闭、加载失败、焦点返回沿用原实现。ID 要区分重复使用同一 src 的两张图，不能用 src 作为唯一键。

保留当前查看器行为：新会话说明默认收起，同次会话跨图保持展开状态；无说明图片隐藏说明但不重置状态；说明在图片下方，展开不改变图片坐标与尺寸；正文样式基础上保留现有 12px 字号，横图说明半宽，纵图右侧预留 24px。不要照早期说明文档恢复已经被后续修改替代的行为。

管理画布继续通过独立「预览放大」入口打开；普通点击图片服务于选择、编辑和拖拽。预览不得改变数据或产生未保存状态。图角 HTTPS 链接优先于放大覆盖层，只点击其余图片区域才放大；管理画布链接仍不直接跳转。不得添加嵌套 button/a 或让透明覆盖层吞掉链接键盘焦点。

现有摄影数据缺少带图角链接的条目，该优先级属于已知未验证项。实施时用可回退的临时夹具检查，不得假称历史上已验证。若继承 hoverZoom，要避免和点击放大同时抢占区域：建议摄影点击放大启用时抑制正文悬停浮层，但保留原字段，关闭点击开关后恢复既有适用行为；此为建议交互策略，需记录最终选择。

## 8. 常见 bug、触发条件与对策

| 风险 | 触发 / 现象 | 对策与检查 |
| --- | --- | --- |
| 白名单漏改 | 画布可选但保存报错，前台退回文章 | UI、前台与服务端三处一起改，保存后重载 |
| 错用旧兜底分支 | 新模板仍是介绍上置、图库双列 | 显式按模板分支，不靠最后 else |
| 图片重复 / 消失 | gallery 与 root:left 同时渲染或切换搬运两次 | 明确唯一内容源，转换一次，切换往返对比数量 |
| 摄影说明丢失 | imageData / 字符串简化遗漏 photographyDescription | 检查所有转换入口，带说明图片保存重读 |
| 图片高度超标 | 裁切内联 max-height:none 覆盖限制 | 对最终框限高，实测横图、长竖图和裁切图 |
| 比例失真 | 强制 width:100% 和固定 height | 按比例同时计算框宽高，不靠 object-fit 掩盖错误框 |
| 页面横向溢出 | 导航+53vw+文本+gap 超出屏幕 | 按 C 预算收缩/折行，检查 scrollWidth 与 clientWidth |
| 画布不一致 | vw 基准不同或编辑按钮挤占布局 | 共用规则，核对画布宿主与有效视口，控件布局外置 |
| 放大没响应 | 选择器仍只查旧模板 | 为两个模板绑定正确容器，入口不存在时不绑定 |
| 点击触发两次 | 每次重渲染/路由加载重复监听 | 幂等绑定，清理监听，检查一次点击仅开一层 |
| 图角链接被遮挡 | 全图透明 button 位于链接上方 | 独立层级、事件目标过滤，鼠标和键盘都测 |
| 编辑时跳转/放大 | 直接把前台覆盖按钮放进画布 | 保留独立预览控件，编辑点击及拖拽仍可用 |
| 说明展开后图片跳位 | 新模板误改查看器布局 | 复用查看器，展开前后测框坐标 |
| 切图顺序错误 | 照搬旧双列 DOM 次序或按 src 去重 | 单列 gallery 顺序，稳定 ID，重复 src 单独保留 |
| 保存后仍被拒绝 | Node 缓存旧校验模块 | 重启实际本地服务，检查实际 API，不能只测磁盘文件 |
| 群组间距变化 | 全局 gap 覆盖组内规则 | 独立组件 12px，内容群组内部 0，说明用自身间距 |
| 坏图/元数据缺失 | aspect 为 0、NaN，首屏跳动 | 复用元数据回退，限制非法比例，加载失败可继续操作 |
| 全站布局回归 | 修改通用 .split-detail-* / img 选择器 | 新模板作用域隔离，只抽取确实一致的规则 |
| 撤回后字段错配 | 切换分多次 dispatch 或绕过历史 | 一次数据操作，撤回/重做后重查 gallery 和正文 |

## 9. 验收矩阵与完成判据

至少检查桌面 1440×900、1280×800、平板 1024×768、手机 390×844、手机横屏 844×390，并补一组较宽桌面尺寸证明 53vw 目标可达。尺寸为建议检查集，不预言这些尺寸下都必须双列；记录实际折行点及原因。
