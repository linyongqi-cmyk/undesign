## 问题与修复

### P2-01｜删除接口忽略撤回历史媒体

- **影响范围**：管理端本地媒体存储；`scripts/local-admin/storage.mjs` 的 `deleteImage()`。
- **复现**：在隔离副本上传 GIF；通过 `history/media` 登记路径；调用孤儿清理后再调用图片删除 API。
- **预期**：历史仍引用媒体时拒绝删除，静态图片仍可读取。
- **修复前实际**：孤儿清理保留文件，但删除 API 返回 200 并删除 GIF，撤回历史会指向不存在的文件。
- **修复**：删除接口同时检查本地保存内容、回收站及当前管理服务登记的撤回历史。
- **验证**：修复前回归断言失败；修复后实际 API 对删除返回 400，图片和字节内容继续返回 200；两次独立历史登记均被保留；回收站图片清理后仍存在，恢复作品返回 200。

### P2-02｜混排组合中的空白图片占位不能保存

- **影响范围**：管理端详情区块保存；`scripts/local-admin/storage.mjs` 的 `mediaComposition` 校验。
- **复现**：在混排组合中保留一个 `src: ""` 的图片占位，并与文字项一起保存。
- **预期**：空白图片组件可保存在草稿/本机，之后再选择图片；区块顺序和文字不变。
- **修复前实际**：校验以“缺少图片”拒绝保存，普通 `imageWithCaption` 则允许空路径占位。
- **修复**：改用共享图片校验，要求图片对象有效，但允许尚未选图的空路径。
- **验证**：现有存储测试和隔离副本实际 API 保存/读取均保留空白图片项及相邻文字。
